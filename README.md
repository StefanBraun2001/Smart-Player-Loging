# Smart Player Logger

Server-side Fabric mod. Keeps two plain text files in a `P_Logger/` folder
in the server directory: a rolling **player activity log** and a
**last-seen history** of every player that ever joined.

Current build: **A0.1.0** (alpha), MC **26.3** only. Build from source with
`./gradlew build` inside `26.3/`.

**Server-side only** - players do not need the mod, vanilla clients can
join as normal.

## Install

Needs Fabric Loader + **Fabric API** on the server. Drop the jar in the
server's `mods/` folder. On first start it creates `P_Logger/`.

## Files (all in `P_Logger/`)

- `config.json` - settings, see below.
- `PA_Logger.txt` - player activity log:
  - `Alice joined the game at 14.10.2026 21:05:33`
  - `Alice left the game at 14.10.2026 21:40:02`
  - `Alice reconnected (Left: 14.10.2026 21:40:02, Return: 14.10.2026 21:42:10)`
  Only the newest `maxLines` lines are kept; the oldest are deleted.
- `PA_Refusals.txt` - refused connections (whitelist, ban, server full, ...), kept
  apart so bots can't push real activity out of `PA_Logger.txt` (see `separateRefusalLog`):
  - `Mallory was refused at 14.10.2026 21:50:00: You are not white-listed on this server!`
  - `Mallory was refused 12 times between 14.10.2026 21:50:00 and 14.10.2026 21:50:25: You are not white-listed on this server!`
  (repeated attempts inside the dedupe window are folded into one line with a count)
- `PA_History.txt` - every player that ever joined, alphabetical (or newest-first, see `History_alphabetic`), with when
  they were last seen (or `Online`):
  `Alice (uuid) - Last seen: 14.10.2026 21:40:02`

Timestamps are `dd.MM.yyyy HH:mm:ss` (24 hour) in the server's local time zone.

## Config

| Key | Default | Meaning |
|---|---|---|
| `maxLines` | `100` | Lines kept in `PA_Logger.txt` (and in `PA_Refusals.txt`, each file separately). |
| `mergeReconnects` | `true` | A player returning within the threshold becomes one "reconnected" line (the leave line is removed, the combined line is appended). |
| `reconnectThresholdMinutes` | `5` | What counts as "reconnecting". |
| `logRefusedConnections` | `true` | Also log refused connections (whitelist, ban, server full, ...) with the reason. |
| `History_alphabetic` | `true` | `PA_History.txt` order: `true` = alphabetical by name, `false` = most recently online first (players currently online on top). |
| `separateRefusalLog` | `true` | Refusals go to `PA_Refusals.txt`. `false` puts them into `PA_Logger.txt` instead. Only used if `logRefusedConnections` is on. |
| `refusalDedupeSeconds` | `30` | Identical refusals (same name + reason) within this many seconds of the first one are merged into one line that says how many attempts there were. `0` logs every attempt separately. |

Missing keys are added on start; invalid values are clamped. If the file
cannot be parsed, it is left untouched and defaults are used for that run.
Changes need a server restart.

## First run import

When `PA_History.txt` doesn't exist yet, it is created and filled from the
world's per-player save files. Minecraft never stored a "last seen" time,
so the file modification time is used as a proxy, and names come from
`usercache.json` / whitelist / ops / ban lists (a player with no known name
shows as `Unknown`). **These lines end with `(estimated)`** until the player
joins again. Backups, restores or file copies can distort these times.

## Limitations

- Refusals before the login phase (version/protocol mismatch, server-list
  pings) have no player name and are not logged.
- Connections that simply drop during login (client gives up, network loss, bots) are not logged.
  Only refusals the server itself sends to the player count, so the console's `lost connection: Disconnected`
  lines are left out on purpose.
- After a crash/kill there is no leave line; PA_History shows those players
  as `(estimated)` at the next start.
- Reconnect merging only works within one server run.
- If another program holds a log file open on Windows, writes fall back to
  overwriting in place.
